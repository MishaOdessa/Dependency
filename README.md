# apkgraph

Инструмент визуализации графа зависимостей пакетов Alpine Linux (apk).
Зависимости получаются без менеджеров пакетов и сторонних библиотек.

Сейчас реализованы этапы 1–4: CLI с настраиваемыми параметрами,
загрузка индекса репозитория (`APKINDEX.tar.gz`), построение транзитивного графа
зависимостей алгоритмом BFS без рекурсии, фильтрация по подстроке, тестовый режим
и вывод порядка загрузки зависимостей.

## Параметры

| Опция | Описание | Обязательна |
|---|---|---|
| `--package` | имя анализируемого пакета | да |
| `--repo` | URL репозитория или путь к файлу тестового репозитория | да |
| `--test-mode` | считать `--repo` путём к файлу тестового графа | нет |
| `--version` | версия пакета | да |
| `--output` | имя файла с изображением графа (по умолчанию `graph.svg`) | нет |
| `--ascii-tree` | вывести зависимости в виде ASCII-дерева | нет |
| `--filter` | пропускать пакеты, в имени которых есть эта подстрока | нет |
| `--load-order` | вывести порядок загрузки зависимостей | нет |

Справка: `python src/main.py --help`

## Обработка ошибок

Программа завершается с понятным сообщением и кодом 1, если:
пустое имя пакета или версия; `--output` не заканчивается на `.svg`;
`--repo` не является http(s) URL; в тестовом режиме файл не найден;
не удалось скачать или распаковать `APKINDEX.tar.gz`;
указанный пакет или версия не найдены в индексе или тестовом файле.
Отсутствие обязательной опции или неизвестная опция даёт код 2.

## Сборка и запуск

Проект использует только стандартную библиотеку Python 3, сборка не требуется.

Вывод порядка загрузки зависимостей на реальном репозитории:
```
python src/main.py --package curl \
    --repo https://alpinelinux.org \
    --version 8.14.1 --filter "so:" --load-order
```

Запуск в тестовом режиме (формат файла: `A: B C`):
```
python src/main.py --package A \
    --repo tests/test_repo.txt --test-mode --version 1 --load-order
```

## Сравнение с реальным менеджером пакетов (этап 4)

При запуске `apk add --simulate curl` в чистом окружении Alpine Linux сначала устанавливаются
самые глубокие зависимости (`ca-certificates`, `brotli-libs`, `nghttp2-libs` и др.),
затем `libcurl` и в самом конце `curl`. Наш алгоритм воспроизводит этот же принцип
(пост-обход графа от листьев к корню), но результаты имеют отличия по трём причинам:

1. **Учёт базовой системы:** реальный `apk` пропускает уже установленные в образе пакеты
   (`musl`, `busybox`, `zlib`), тогда как наш инструмент анализирует индекс репозитория с нуля.
2. **Подмена виртуальных токенов:** `apk` заменяет виртуальные зависимости (`so:...`, `/bin/sh`)
   на имена предоставляющих их пакетов, а наш граф сохраняет исходные токены из поля `D:`.
3. **Порядок независимых пакетов:** пакеты одного уровня, не зависящие друг от друга,
   `apk` сортирует по внутренним правилам, а наш инструмент — в порядке их перечисления в `APKINDEX`.

## Демонстрация и проверка

```
bash tests/demo.sh
```

Скрипт проверяет работу BFS и порядка загрузки в тестовом режиме (графы с циклами,
ромбами и фильтрацией), анализ пакетов из реального репозитория (`busybox`, `curl`)
и обработку ошибок.
